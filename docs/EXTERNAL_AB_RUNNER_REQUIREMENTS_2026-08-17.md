# External A/B Runner Requirements

External baseline execution is an optional, approval-gated evidence lane for Hermes, OpenCode, and DeepSeek Harness. A valid run requires an exact immutable revision, task-manifest digest, protocol fingerprint, disposable workspace, seed digest when required by the manifest, credential isolation, deny-by-default network policy, capability-aware preflight, signed receipt, and reproducible result artifact.

The pinned orchestrator validates the manifest before planning a pinned lane. Floating revisions, missing seed digests, invalid workspace/budget policy, missing executables and unavailable capabilities remain `not_run` or `blocked`. Approval uses `noesis.external-approval.v1`: an HMAC receipt binds the exact command digest, argv-derived plan, workspace, revision, protocol fingerprint and task-manifest digest, has a bounded expiry, and must be consumed exactly once through a transactional SQLite/WAL receipt store. Concurrent consumers have one winner, committed consumption survives reopen, and malformed/corrupted stores fail closed. A durable execution journal records `consumed`, `started`, `completed` or `abandoned`; interrupted or abandoned execution never auto-reuses a receipt and requires a new approval, while completed execution is `no_replay`. Missing, expired, mutated or replayed approval receipts remain denied; approval must never be coerced into `passed`, `failed`, or a comparative ranking.

## Durable execution-journal binding

An explicitly approved lane must durably record `consumed` and `started` in SQLite/WAL before the child process is launched. A non-timeout return records terminal `completed` with the structured runner status (`passed` or `failed`); a timeout or raised runner exception records `abandoned`. Recovery never reuses an interrupted or abandoned approval and returns `issue_new_approval`; completed approvals return `no_replay`. This is local governance evidence only and does not create external execution or comparative-readiness evidence by itself.

The bounded-local acceptance contract is: dry-run remains `not_started`; execution without an approval receipt is denied; valid approval is consumed exactly once; journal transitions survive reopen; timeout is a nonzero CLI exit with `abandoned`; and no `ResourceWarning` is emitted under Python 3.14 strict testing.

Actual Hermes, OpenCode, or DeepSeek Harness execution remains `NOT RUN` until exact revisions, executable availability, disposable environments, operator approval, and signed result evidence exist.
