# Operator Case Bundle Runbook

The readiness-only bundle is generated by `scripts/build_operator_case_bundle.py`. It packages the exact case IDs, lane revisions, protocol fingerprint and security policy needed for a later operator-run external comparison.

## Contract

The emitted artifact uses `noesis.operator-case-bundle.v1` and contains a deterministic manifest digest, bundle digest, required lane list, lane readiness state and bounded operator steps. It is an export contract, not an executor.

| Field | Requirement |
|---|---|
| `mode` | Always `readiness_only`. |
| `execution_allowed` | Always `false`. |
| `automatic_execution` | Always `false`. |
| `approval_required` | Always `true` before any external command. |
| `network_policy` | `deny`. |
| `credentials` | `absent`. |
| `workspace_mode` | `disposable`. |
| `case_ids` | Unique, non-empty and fixed before execution. |

A complete manifest with all exact revisions produces `ready_for_operator_preflight`. Missing revisions produce `not_run`; unsafe policy, invalid schema, duplicate case IDs or malformed identity produces `blocked`. None of these statuses launches a provider or creates a score.

## Operator sequence

The operator verifies the manifest and bundle digests, confirms pinned executables and environment digests on the matching host, obtains explicit approval, runs the provider-neutral lane command in the disposable workspace, ingests the signed lane receipt and case receipts, and finally builds the comparative report. The bundle contains no provider credentials and does not invoke a command itself.

The current repository bundle is a readiness artifact only. Native Windows/macOS execution and Hermes/OpenCode/DeepSeek Harness execution remain `not_run` until matching hosts, exact revisions, executable availability, disposable environments and explicit approval are present.
