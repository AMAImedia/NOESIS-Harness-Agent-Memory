# Миграция на Python 3.14-only — 2026-08-17

## Решение

NOESIS-Harness-Agent-Memory переходит на **Python 3.14-only** для следующего поколения agent-OS. Метаданные пакета теперь требуют `Python >=3.14`, classifiers рекламируют только Python 3.14, GitHub CI-workflow использует единую Python 3.14 test matrix, инструкции runtime в README приведены в соответствие с этой политикой.

Это намеренное ломающее изменение совместимости, запрошенное владельцем. Это ещё не заявление, что нативная портативность завершена: текущий sandbox экспонирует Python 3.12, Python 3.14 локально не установлен, и верификация native Windows/macOS 3.14 остаётся pending.

## Обязательные verification gates

| Gate | Требование | Статус |
|---|---|---|
| Метаданные пакета | `requires-python = ">=3.14"`; classifier только для 3.14 | Реализовано |
| CI | Тесты, lint и сборка используют Python 3.14 | Реализовано в workflow; удалённая верификация CI pending |
| Локальный runtime | Доступен интерпретатор Python 3.14 | Недоступен в текущем sandbox |
| Полная регрессия | 200+ тестов проходят под Python 3.14 | Ожидает интерпретатор/runner |
| Native Windows | Portable launcher, supervisor, SQLite cleanup, data roots и artifact startup под Python 3.14 | Ожидает native runner |
| Native macOS arm64 | Те же проверки под Python 3.14 | Ожидает native runner |
| Packaging | Self-contained `.exe` и `.app` или документированная стратегия embedded-runtime | Будущая фаза |
| Release evidence | SHA-256 manifest, версия интерпретатора, платформа, итоги тестов и вывод аудита | Будущая фаза |

## Следствие для совместимости

Репозиторий больше не обещает установку на Python 3.9–3.13. Существующие тесты всё ещё могут выполняться на более старом интерпретаторе при прямом запуске из дерева исходников, но это не поддерживаемая конфигурация релиза. Документация и CI не должны называть более старые версии верифицированными продакшен-целями.

## Архитектурное следствие

Python 3.14 — это runtime для control plane, agent runtime, provider-адаптеров, исполняемых skill child-процессов и инструментов packaging. Ядро остаётся stdlib-first. Сторонние компоненты могут интегрироваться только за явными адаптерами и не должны молча становиться обязательными зависимостями memory/security-ядра.

## Следующий шаг реализации

Прежде чем реализовывать широкие execution-функции, провести source/license/security аудит Cloudflare OS, Hermes Agent, OpenCode и связанных проектов. Использовать архитектурные контракты и тестовые идеи, где они совместимы; не копировать код и не вендорить зависимости, пока не зафиксированы лицензионная совместимость, provenance и trust boundaries.
