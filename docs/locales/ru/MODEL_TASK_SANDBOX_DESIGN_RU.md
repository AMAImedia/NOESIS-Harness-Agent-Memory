# Модельные лейны: дизайн сети с ограничением выполнения (RU)

Сжатое техническое зеркало `docs/MODEL_TASK_SANDBOX_DESIGN.md` (английский
первичен). Статус: дизайн + каркас, блокер Gate 7. Ничего не выполнялось.

## Проблема

`task_execution_class="model_task"` требует исходящего доступа к pinned
LLM-API, а политика лейнов — deny-by-default. Текущая санитизация окружения в
адаптере (чистка кредов, одноразовая рабочая директория) НЕ является сетевой
границей на уровне ОС: дочерний процесс может открыть любой сокет. Честно
заявить сетевую изоляцию нельзя — поэтому модельные лейны остаются `not_run`.

## Варианты (Windows-first, честно)

| Вариант | Оценка |
|---|---|
| AppContainer / LPAC + `internetClient` | Настоящая граница ядра; нужен подписанный/разрешённый exe или runas-токен, нативный тулинг вне stdlib-only. Фаза B. |
| WFP per-app фильтр | Требует админа и близок к драйверам; отвергнуто для этого репо. |
| Job Objects | Сети не контролируют вовсе; честное отклонение как сетевой границы. |
| Proxy-jail (выбрано, Фаза A) | Локальный stdlib-прокси на 127.0.0.1, CONNECT только на allowlist хостов; без админа и MITM. Оговорка: раннер, игнорирующий proxy env, убегает — enforcement advisory. |
| Linux bwrap `--unshare-net` | Эталонная реализация уже есть (`sandbox_bwrap.py`); её чеки — образец для конформанса. |

## Фаза A (текущий каркас)

`noesis_harness/model_task_sandbox.py`:

- `ModelTaskSandboxBackend(backend_id="model-task-proxy", host_platform="any")`;
  allowlist валидируется fail-closed (пустой/невалидный хост → ValueError;
  схемы, порты, wildcards, пути отвергаются).
- `available=False`, пока инъецированный `verify_proxy_boundary()` не вернёт
  True; исключение верификатора = провал.
- `run()` всегда возвращает blocked `SandboxResult` без подпроцессов; даже при
  проверенной границе — `model_task_execution_runtime_not_bound`.
- `proxy_env_for(allowlist)` — детерминированные HTTP(S)_PROXY/NO_PROXY,
  указывающие на `127.0.0.1:<port>`; NO_PROXY исключает только loopback,
  allowlist-хосты через прокси идут обязательно.
- Ноль subprocess в модуле — закреплено тестом.

Планируемый рантайм Фазы A (отдельный модуль): loopback-прокси с CONNECT
allowlist, логом отказов и health-пробой; прокси запускает оператор, не каркас.

Пробы: A1–A3 статические (юнит), A4/A5 рантайм (deny/tunnel через прокси),
A6 честность — ребёнок без proxy env ДОЛЖЕН иметь прямой доступ; факт
фиксируется как известная лазейка.

Отказы: прокси не запущен → egress ломается закрыто (безопасно); хост вне
allowlist → deny + лог; игнор proxy env → побег (advisory, задокументировано).

## Фаза B — AppContainer LPAC

Подписанный/разрешённый exe, профиль только с `internetClient`, ACL-deny на ФС
вне workspace, restricted-token fallback. Пробы: токен контейнера, отказ записи
ФС, отказ сокета на уровне ОС, конформанс через `sandbox_backend`.

## Граница заявлений

Фаза A — НЕ граница уровня ОС: это advisory-сдерживание через переменные
окружения. Без MITM и инспекции трафика. Ничего не выполнялось:
`execution_claim: not_run`. Текущие доказательства структурные (тесты);
рантайм-квитанции требуют прокси-рантайма, проб A4–A6 и одобрения оператора по
`docs/PINNED_LANE_OPERATOR_PREFLIGHT.md`.
