# Дополнение: мостик к t-search-harness

Необязательная, отключённая по умолчанию интеграция
[turbo-llm/t-search-harness](https://github.com/turbo-llm/t-search-harness)
(Apache-2.0, модель T-Search) с памятью агента NOESIS. Лежит в `addons/` и НЕ
импортируется ядром `noesis_harness/` (правило «ноль зависимостей»).

## Что делает

`t-search-harness` — это «линза» раундового поиска/ранжирования: до N раундов,
каждый с чистым контекстом, переносятся только куски, которые модель сама
сохранила через `save_and_advance`. Ей нужны две вещи, которые даёт оператор:

- LLM-эндпоинт, совместимый с OpenAI (рабочая точка T-Search);
- поисковый бэкенд (контракт `SearchClient`: `search(query, top_k) -> str`).

NOESIS закрывает поисковый контракт классом `NoesisMemorySearchClient`, который
отдаёт **сам журнал событий NOESIS как корпус**. То есть `retrieve(query)`
ранжирует самые релевантные события из собственной памяти агента и возвращает
сфокусированный контекст вместо всей проекции.

## Точка интеграции (Трек C: длинная память)

Это подключаемый retrieval-колбэк (правило AGENTS.md №2: «если добавляете
сжатие, оно должно быть подключаемым колбэком, а не жёсткой зависимостью»).
Базовый recall остаётся детерминированным и без LLM; линза t-search
используется только когда оператор явно её включит и даст LLM-эндпоинт. Она
дополняет, а не заменяет существующую replay-проекцию.

## Граница честности

- Отключена по умолчанию (`TSearchBridgeConfig.enabled = False`).
- `retrieve` завершается строго: `not_run` когда выключена, `blocked` когда
  harness не установлен или не задан LLM-эндпоинт. Никогда не утверждает, что
  память «улучшилась» или прогон прошёл, если это не так.
- t-search-harness заточен под модель T-Search; поведение на других моделях —
  наилучшее усилие, не рекламируется как паритет или превосходство.
- Нет утверждений о нативном/внешнем исполнении или превосходстве конкурентов.

## Файлы

- `addons/t_search_bridge.py` — ленивый импорт `retriever_agent`; на момент
  импорта только stdlib.
- `tests/test_t_search_bridge.py` — 8 тестов, все зелёные без установленного
  t-search-harness (guard-пути + адаптер поиска по памяти NOESIS).

## Будущее (опционально)

- Заменить `NoesisMemorySearchClient` на реальный ретривер (BM25 / эмбеддинги),
  когда оператор его предоставит; мостик уже говорит на контракте `SearchClient`.
- Когда появится совместимый с OpenAI эндпоинт T-Search (или совместимой модели),
  запустить сквозной `retrieve` и записать доказательства в рамках существующих
  гейтов честности.
