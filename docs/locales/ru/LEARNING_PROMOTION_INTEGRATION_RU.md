# Learning Promotion Integration Contract

Это supplemental localization English primary contract, связывающий terminal task outcomes из durable task/session event stream с human-governed learning promotion pipeline без automatic skill activation.

| Поверхность | Контракт |
|---|---|
| Durable event stream | `PromotionEventBridge` replay-ит append-only `task_state_changed`; только `committed` и `failed` допускаются к capture, а `cancelled` явно отклоняется. |
| Terminal mapping | `committed` становится успешным promotion outcome, `failed` — failure outcome; active/review/planned/unknown states bridge игнорирует. |
| Policy simulation | `OwnershipPolicySimulator` выводит решение из authoritative task/session metadata и explicit runtime owner lookup, затем использует `RuntimePolicySimulator` для deterministic digests. Session mismatch, missing owner, denied scope, malformed metadata и lookup errors fail closed. |
| Durable checkpoints | Пишутся `started`, `completed`, `denied` checkpoint events по source task event ID; completed/denied не replay-ятся. Existing receipt переиспользуется по experience ID. |
| Evaluator registry | Версии evaluator регистрируются явно и уникально; unknown/duplicate versions fail closed. Evaluator создаёт deterministic holdout cases, но ничего не продвигает автоматически. |
| Promotion operations | Capture, evaluate, propose, approve, promote и rollback выполняются явными вызовами. Единственная lifecycle entry point — `TaskExecutionBridge.poll_promotion_events(operator_trigger=True)`; `execute()` не poll-ит и не promote-ит implicit. |
| Operator administration | `AdministrativePolicyStore` — reviewed session-bound source для grant/revoke reviewer operations. Требует active administrator session и `admin:reviewers`. Каждая принятая mutation получает HMAC-signed `noesis.signed-mutation-receipt.v1` audit receipt; повторное состояние отклоняется как conflict. Optional `CoordinatedMutationJournal` пишет phases `prepared`, `committed` или `aborted`. Prepared action без terminal record имеет статус `incomplete` и не auto-promote-ится и не reconciles-ится скрытно. `OperatorSessionActionExecutor` выполняет explicit idempotent open/close actions с тем же signed receipt contract; optional `POST /api/operator-sessions` и `POST /api/admin/reviewer-policy` только валидируют и делегируют injected handlers.
 |
| Operator approval UI | `PromotionApprovalAction` — versioned non-secret envelope для `approve`, `reject`, `rollback`. `OperatorSessionRegistry` persistent хранит operator sessions, scopes и bounded TTL и выводит active `OperatorAuthContext`. `ReviewerAuthorizationStore` persistent хранит grants/revocations; missing, revoked, expired или scope-mismatched authorization fail closed. `PromotionActionExecutor` выполняет только explicit proposal operations, требует independent authorized reviewer, подписывает receipt и хранит idempotent action record. Optional `POST /api/promotion-actions` валидирует envelope и передаёт action вместе с configured context в injected handler; HealthServer сам promotion не выполняет. |
| Operator telemetry | Lifecycle и denial events bounded/redacted; публикуются в optional `learning_promotion` section read-only HealthServer telemetry и SSE snapshot. |
| Activation | Integration default — `activate=False`; task completion, policy simulation, UI action validation, action executor и evaluation не создают active skill pointer. |
| Production lifecycle facade | `ProductionLearningLifecycle` соединяет durable task store, `PromotionEventBridge`, injected runtime-owned policy simulator и `PromotionActionExecutor`. `capture_terminal_events()` требует `operator_trigger=True`; `handle_operator_action()` остаётся отдельной authenticated operation. Readiness явно сообщает, что automatic evaluation, approval, promotion и activation отключены. |
| Durable promotion state | `LearningPromotionPipeline` хранит receipts, evaluations, proposals, previous-active metadata и evaluator manifests в SQLite/WAL. Reopened pipeline восстанавливает bounded state; malformed или conflicting evaluator manifests fail closed. |
| Retry/conflict boundary | Повтор одинаковых capture, holdout evaluation или proposal возвращает existing record. Identity с другим payload, holdout manifest или proposal content вызывает явный conflict вместо скрытого overwrite. |

Events: `experience_captured`, `holdout_evaluated`, `promotion_proposed`, `promotion_approved`, `promotion_completed`, `promotion_rolled_back`, `promotion_blocked`. Telemetry содержит identifiers, states, counts, digests и bounded denial reasons; content-like fields, credentials и API keys recursively redacted.

Bridge replay-safe для повторного poll и нового bridge с тем же checkpoint path. `completed`/`denied` source events пропускаются; незавершённый `started` может быть повторно обработан, а receipt lookup предотвращает duplicate capture после сбоя. EventStore исправляет только malformed final JSONL tail; non-tail corruption остаётся hard failure.

Operator actions отдельно replay-safe по `action_id`: completed action возвращает сохранённый signed receipt и не повторяет transition. `verify_signed_mutation_receipt` выявляет tampering или неверный signing key. Optional `CoordinatedMutationJournal` использует prepare/apply/commit coordination; `incomplete()` показывает prepared actions без terminal record, а `abort` делает interrupted operation явной. Это coordination, а не claim cross-file atomicity. Identity/session/scope mismatch fail closed и пишут bounded `promotion_action_denied` telemetry; replay пишет `promotion_action_replayed`. `OperatorSessionRegistry` восстанавливает sessions из append-only events и отклоняет inactive, closed или expired sessions. Administrative reviewer grants требуют active administrator session с `admin:reviewers`; unauthorized grant/revoke отклоняется до policy mutation, повторные состояния отклоняются как conflicts. При malformed final tail EventStore удаляет только этот tail, а incomplete mutation остаётся fail-closed; non-tail corruption не исправляется. Reviewer authorization persistent и append-only: grant должен совпадать по operator/session и required scope; missing/revoked grant отклоняется. Approval требует independent authorized reviewer относительно experience owner; `reject` допустим только из `review`, `rollback` — только из `promoted` и не активирует skill. Approval и activation никогда не выводятся из task-event checkpoint.

Этот слой не запускает skill content, не выбирает evaluator implicit, не активирует skill автоматически и не делает claim полной autonomous learning capability. `SQLiteAdministrativeBackend` — optional single-store SQLite/WAL backend, где operator sessions, reviewer grants и signed mutation audit rows коммитятся в одной database transaction. При failed transaction state mutation и audit row не остаются частично. `AdministrativeMigrationAdapter` хранит versioned modes `legacy`, `dual_read`, `sqlite`, блокирует direct legacy-to-sqlite cutover, сравнивает authoritative identity/scopes/active state перед adoption и поддерживает explicit rollback в `legacy`. `AdministrativeActionRouter` по умолчанию выбирает legacy handler, блокирует routing в `dual_read`/`sqlite` при failed verification и выбирает SQLite handler только после explicit verified mode transition. Его `health_handler()` совместим с injected HealthServer mutation handler contract и пишет bounded routing evidence event. `promotion_handler()` разбирает versioned `PromotionApprovalAction` envelope и делегирует в `handle()` выбранного real executor; reviewer/session authorization не обходится. TTL timestamps сравниваются semantic state, а не byte equality. Automatic cutover остаётся запрещённым. `OperatorMigrationModeSource` — append-only operator-owned source режимов с безопасным default `legacy`; direct `legacy` в `sqlite` отклоняется. HealthServer принимает source при startup, публикует `/api/readiness` и добавляет `migration_readiness` в telemetry/health evidence. Readiness snapshot сообщает `legacy`, `dual_read`, `sqlite`, `blocked` и `rollback_available`; blocked migration отображается в разрешённом UI status `unavailable`, но machine-readable snapshot сохраняет `blocked`. Authenticated POST `/api/admin/migration-mode` принимает versioned `noesis.migration-mode-action.v1`, требует injected operator context и возвращает HMAC-signed mode-change receipt. Self-contained Cloudflare-style control-plane UI показывает readiness card, rollback state и mode-change controls; SSE telemetry обновляет этот panel. Runtime activation остаётся отдельным capability-gated этапом. Production facade — это binding и policy boundary, а не autonomous learning loop: task completion не запускает evaluation, approval, promotion или activation как скрытый side effect. `PromotionIntegration.snapshot()` показывает только bounded counts и evaluator manifest digests; payload и skill content не попадают в operator telemetry.

Implementation: `noesis_harness/learning_promotion.py` и `noesis_harness/promotion_integration.py`; lifecycle wiring: `noesis_harness/execution_bridge.py` и `noesis_harness/portable_launcher.py`; HTTP contract: `noesis_harness/health_server.py`; tests: `tests/test_learning_promotion.py`, `tests/test_promotion_integration.py`, `tests/test_execution_bridge.py` и `tests/test_ui_contract_health.py`. Gate 2 tests проверяют restart reconstruction, evaluator manifest conflict, duplicate idempotency и bounded state.
